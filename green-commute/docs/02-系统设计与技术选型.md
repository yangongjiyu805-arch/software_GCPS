# 实验二：系统设计与技术选型

## 1. 架构决策

采用**单体模块化REST后端 + 事务型Outbox事件**。Web端同源 HTML/CSS/JS，无需构建；Python FastAPI负责JWT登录、OpenAPI、参数约束，SQLAlchemy ORM负责事务和数据库结构。本地 SQLite便于课程复现；Docker示例切换 MySQL 8。相较于微服务+消息队列，单体Outbox的搭建负担小，且能展示“事务内产生事件，独立消费可重试”的EDA思想。

实际事件处理：`submit_trip` 在事务中同时保存行程和Outbox；提交之后同步调用 `process_pending` 快速响应；`worker.py` 提供异步轮询恢复路径。生产级多消费者队列、事件租约及死信管理尚未实现，故应限定为课程级单机演示方案。

## 2. 模块设计

- `app/main.py`：路由与输入约束、用户身份、角色权限、序列化输出。
- `app/models.py`：数据库实体和唯一约束。
- `app/services.py`：整数碳减排计算、原子兑换、幂等处理、事件消费、聚合统计。
- `app/security.py`：PBKDF2密码哈希、JWT签发和校验。
- `app/static/`：浏览器单页客户端，包含登录、居民看板、行程、商城、积分流水、订单、商户及管理视图。
- `scripts/worker.py`：轮询待处理事件，实现失败重试能力。

## 3. 数据模型（与运行源码一致）

| 表 | 主键/核心字段 | 关键约束/关系 |
|---|---|---|
| `users` | id, username, password_hash, role, balance | username唯一；balance整数 |
| `trips` | id, user_id, client_trip_id, mode, distance_m, saved_g, points, status | (user_id,client_trip_id)唯一 |
| `point_transactions` | id, user_id, kind, reference_id, delta | (kind,reference_id)唯一，业务幂等键 |
| `products` | id, merchant_id, cost, stock, active | 商户关联；库存非负由条件更新保证 |
| `redemptions` | id, user_id, product_id, points, status | 关联商品/居民，保留兑换时商品名和成本快照 |
| `settlements` | redemption_id, merchant_id, points, status, settled_at | 与兑换单1:0..1关联；清算单由事件产生 |
| `outbox_events` | id, kind, ref_id, state, attempts, error | (kind,ref_id)唯一；消费失败可重试 |

## 4. 积分一致性设计

1. 行程业务键 `(user_id,client_trip_id)` 唯一，避免用户反复提交同编号行程。
2. 减排量保存为 `saved_g` 整数、距离为 `distance_m` 整数，积分为整数。不存在浮点小数积分。
3. Outbox 与新行程在同事务提交；消费者发放余额变动、台账和行程状态在同一事务。
4. `point_transactions` 的 `(kind,reference_id)` 唯一，事件重放不能形成重复积分流水。
5. 兑换时使用条件UPDATE：`users.balance>=cost` 与 `products.stock>=1`；成功时生成订单、负向台账和新Outbox事件，共同提交。
6. 清算只允许 `FULFILLED` 订单，重复清算直接返回已结算而不再计入积分。

## 5. 逻辑状态机

- 行程：`PENDING → AWARDED`（成功发放）。事件处理失败则保持`PENDING`，等待重试。
- 订单：`PROCESSING → TO_FULFILL → FULFILLED`。
- 清算：`PENDING → SETTLED`。**清算不等于真实货币转账**，仅记录积分结算状态。
- Outbox：`PENDING → DONE`；失败增加 `attempts` 并保留待重试状态。

## 8. 技术风险与取舍

- 演示环境：SQLAlchemy `create_all` 适合第一次建库，生产演进需Alembic迁移版本控制。
- 演示账户：默认演示密码和密钥仅供本地课程，不能暴露在公网上。
- 并发：通过事务条件UPDATE处理扣减竞争，SQLite并发集成用例通过；尚无压力测试报告。
- 碳核算：固定系数只演示计算算法，实际需核验路线、时间、出行凭证和地区因子。
- 审计：未实现订单退款、风控、完整操作日志、限流或财务支付。
