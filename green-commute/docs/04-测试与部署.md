## 3. HTTP业务链复验

启动 `uvicorn app.main:app --port 8000`，运行 `python scripts/demo_flow.py`（本次取证时通过 DEMO_BASE_URL 指向8765测试端口）：

- `POST /api/trips` 模拟30km公交，返回 `+33` 分；
- `POST /api/redemptions`兑换12分商品，订单转为待核销；
- 商户核销完成后，管理员清算结果`SETTLED`；
- 另存实际调用结果在 `docs/evidence/demo_flow.json`（依环境中既有示例行程，最终余额可能高于本次净增21分）。

## 4. 部署架构与步骤

**本地**：安装依赖，配置 `JWT_SECRET`，运行 `uvicorn app.main:app --host 0.0.0.0 --port 8000`，数据库首次自动生成；访问浏览器和 `/docs`。

**Docker Compose示例**（未在当前工作环境实际部署）：`docker compose up --build -d`。配置MySQL8容器、FastAPI API容器与Outbox worker容器，建立MySQL健康检查与持久卷。对公网发布之前需要替换默认凭证/密码并接入HTTPS反向代理、密钥管理与备份。

**操作注意事项**：SQLite单机适合课程演示，多容器与并发推荐MySQL；需明确部署节点与HTTPS入口，生产应创建非演示管理员并禁用固定凭证。当前 Docker 引擎不可用，故未声称执行过真实容器部署。

## 5. 未覆盖及未来增强

1. **缺少真实出行证明**：防作弊须接入行程证据与反刷校验，否则用户可以任意输入距离。
2. **缺少退款闭环**：订单取消、商品退货、积分反冲与库存归还应独立建模并测试。
3. **事件可靠性扩展**：多Worker需队列领取锁、重试上限与死信箱；当前课程原型以简单待处理重试演示。
4. **缺少全面质量指标**：未进行真实浏览器自动化UI截图、跨浏览器兼容测试、正式负载压测和真实MySQL容器测试。
5. **安全生产化**：需补强限流、CSRF策略评估、HTTPS、生产用户配置、审计、备份及依赖安全扫描。
