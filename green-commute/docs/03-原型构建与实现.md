# 实验三：系统原型构建与实现

## 1. 原型功能清单

启动后端即可从网页端访问：

1. 登录页面：切换居民、商户、管理员演示账号，认证成功后按角色显示菜单。
2. 居民工作台：账户积分、模拟减排、行程数量及里程、最近7天积分柱状趋势。
3. 行程上报：选择方式与距离，实时预估碳量与积分，自动生成防重行程号。
4. 积分商城：6个初始化商品，按品类筛选、显示库存与积分价格，并确认兑换。
5. 积分账本：查看正负流水与业务关联信息。
6. 兑换记录：显示订单履约状态。
7. 商户工作台：上架商品、查看订单、点击核销。
8. 管理后台：统计信息、清算单、已核销订单清算、Outbox事件重试。

## 2. 示例用例及计算

`POST /api/trips {"client_trip_id":"BUS-0001","mode":"bus","distance_km":"30"}`：

- `distance_m=30000`
- `saved_g=30000 × (180−70) / 1000 = 3300g`，即3.3kg
- `points = floor(3300/100)=33`
- 提交行程与`TripSubmitted`事件后，事件消费者写入 `+33` 流水与余额，并将行程标记`AWARDED`。

商品价格12分，兑换事务执行条件扣减余额及库存，创建兑换单`-12`流水与`RedemptionCreated`事件。商户核销后运营可清算该订单。

## 3. 源文件与可运行环境

`README.md`是主运行指导文档；`requirements*.txt`列出了运行和测试依赖；`Dockerfile`与`docker-compose.yml`包含容器部署样例。实测使用Python 3.13、FastAPI 0.128、SQLAlchemy与 SQLite 的本地配置。前端使用原生JavaScript的Fetch API，浏览器同源访问REST接口。

## 4. 关键代码说明

- `calculate()`：先把最多两位小数公里值转换为整数米，按整数算出减排克数、积分；非法输入直接拒绝。
- `submit_trip()`：使用用户与行程编号唯一性，保持重复上报的幂等行为。
- `process_pending()`：处理 `TripSubmitted`/`RedemptionCreated`；以流水业务键和事务保障消费重放安全。
- `redeem()`：`UPDATE ... WHERE balance >= cost` 与 `UPDATE ... WHERE stock >= 1`处于单数据库事务，任一检查失败则整体回滚。
- `require_role()`与资源所属判断：对商户订单查询、核销、居民流水等提供权限约束。

## 5. 敏捷迭代与Git落地

项目目录可以直接初始化Git并按真实修改提交，已配置`.gitignore`排除数据库、环境密钥等。仓库的本地示例提交不是4—5名成员分别提交的记录。正式课程团队需采用Feature Branch、Pull Request合并、每周Sprint评审与真实Commit日志；README、docs、tests与代码共同纳入Git版本。

建议看板列：`Backlog → Todo → In Progress → Review → Done`。用户故事对应验收结果和自动测试，Sprint结束时以可运行的服务而不是仅静态文档作为增量。
